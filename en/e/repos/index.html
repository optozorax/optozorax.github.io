#My coding projects

All the projects that involve programming.

LinkDescription
space_objectsA library for working with coordinate systems and transformations between them. It abstracts working with coordinate systems so powerfully that I use it in every project of mine that has even a little bit of graphics.
portals_openglRendering portals with OpenGL; it supports not only recursive portals, but volumetric ones too.
path-tracingI completely rewrote this ray tracer from scratch, improved the architecture, and added the ability to render not only with path tracing (photorealistic graphics) but also with ray tracing (fast, but not as realistic). Used in many of my other projects.
ray-tracingA fork of some guy's code from GitHub. I chose his code in particular because it was as simple as it gets, compiled without problems, and gave impressive results. With this code I understood for the first time how ray tracing works, and decided to dig into it even deeper by improving the code and adding a couple of features.
keyboard_layoutMy keyboard layout plus tools for recording and displaying keypress statistics.
TinyWindowsGraphicsMy second wrapper over WinAPI functions. It inherits the ideas of GraphWinApi, but with a much more thought-out architecture. It also contains a wrapper over AGG for anti-aliased drawing, as well as EasyBMP and STB for saving images to files. It's used in many of my other projects, though not as a library for building applications, but as a graphics library. And I think the part responsible for colors, points and drawing should be moved out into a separate lib.
olympSolutions to competitive programming problems. So far, all the problems in this repository are taken from and checked on olymp.nstu.ru (in Russian).
partially-drawing-image-algorithmAn algorithm for drawing an image that hasn't been fully received yet. It defines not only the order in which the pixels are traversed, but also the algorithm for drawing the image itself. I used it for ray tracing, to show in real time what was taking a very long time to render. Running time with respect to the number of pixels: linear. Unfortunately, it depends on TWG, so nobody except me will be able to use it.
GraphWinApiA wrapper over WinAPI functions. One of my first libraries and big programs in C++, so the code is really ugly.
slovo-gonkaA program for learning English words. The interface is as simple as it gets: a word in English and four buttons where you have to choose the right answer. Built on TWG. I don't actually learn words with it *facepalm*.
slovo_gonki2A project to write a new app for learning English words, together with Ldaon. Still in development.
fast_tree_point_in_polygonAn attempt to invent an algorithm for checking whether a point lies inside a polygon by decomposing the polygon's space into a tree. The attempt failed, or maybe I just didn't have enough patience.
keyboardAn attempt to write code that finds the optimal layout based on the idea of chords. I abandoned the project because of the incredible complexity I had piled up for myself (I wanted to account for layers and duplicated keys at the same time). Layout development diary (in Russian).

#University lab assignments

I posted them so I could tell my classmates look on GitHub to see how I did it, and also to have lots of green squares in my daily activity, as if to say I'm not just goofing off. There are also some genuinely good repositories among them.

Link, NameCourse description
cgi_labs, Computer graphics (in Russian)We write simple applications using OpenGL.
numerical_methods, Numerical methods (in Russian)We write methods for solving systems of linear equations. But the systems aren't given in a dense format, but in a sparse format with lots of zeros. And they have to be solved in that same format. This is used in the finite element method (FEM), where each element has only a few neighbors, and when RAM is limited to gigabytes and time to weeks (if you build the matrix with all its zeros, you won't find enough RAM to store it all or enough time to wait for it).
labs_emf, Equations of mathematical physics, part 2 (in Russian)We implement methods for solving the differential equations from the first part of this course, using methods similar to FEM. The bad thing about this course is that the course manual is terribly written, nothing makes sense, the research tasks are pointless, and we don't simulate any physical processes, only abstract spherical cows in a vacuum. On the plus side, my term project came out almost divine.
optimization_methods, Optimization methods (in Russian)We write and study methods for finding the minima and maxima of multivariate and one-dimensional functions.
matstat_rgz, term assignment in mathematical statistics (in Russian)The LaTeX is just really pretty, that's all.
labs_machine_learning, Project work, part 2 (in Russian)We study computer vision with convolutional neural networks, using cat and dog recognition as an example.
numerical_simulation_of_ODEWe write solvers for ordinary differential equations and apply them to some physics problems. Since the course was only introduced in our year, I tried to write my own course manual for it.
labs_translation_methods, Compiler construction (in Russian)We write our own compiler for a very small subset of C. The course is meant to teach how compilers work and to study programming concepts such as finite state machines and grammars. Most of the code wasn't written by me.
cryptography, CryptographySimple labs for mastering basic cryptographic concepts, such as letter frequency, hashes, the Diffie–Hellman protocol, public and private keys, symmetric and asymmetric encryption. The coolest thing in this repository is a program that automatically decrypts text encrypted by permuting the letters of the alphabet (a simple substitution cipher). For this I use a genetic algorithm and clever metrics based on bigram and trigram frequencies. See folder 1 for it.
assemblerLearning MASM assembly and using it from C++.
resources_control_labs, Resource management in computer systems (in Russian)We write programs that use Linux features such as fork, pipe, execl, openp. Thanks to this course I realized that either I don't understand Linux, or it has a terrible architecture!
prolog, Prolog (in Russian)We write simple programs in this language.
machine_learningSome kind of decision trees, I can't make heads or tails of it.
