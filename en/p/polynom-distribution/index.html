Approximating a data distribution with a polynomial

I had a lot of flight data from a micro drone and wanted to make a nice smooth plot... I couldn't find a ready-made solution on the internet.

#Introduction

I flew a lot of laps with my drone at home and timed them automatically: there were 8.5 s laps, a lot of 10 s laps, a fair number of 15 s laps, and very few 30 s and 60 s laps. Of course, I could just plot a histogram to visualize these results, but I wanted some kind of smooth curve, so that I wouldn't have to pick the bin width of the histogram, and so that this smooth curve would take into account how close the results are to each other.

I tried googling it and found nothing. Or I found something but didn't understand a thing (like this paper: it started with a bang well, but then wandered off somewhere and lost me). So I had to invent everything myself. I sat over a notebook for a bit, thought it through, then coded for a while and got a result (not right away, of course). In this post I'll explain how to approximate a one-dimensional distribution with a polynomial of degree N. The resulting algorithm has complexity , where is the number of points.

#Algorithm

Input:

  • : an array of M values whose distribution we want to approximate.
  • : the degree of the resulting polynomial.
  • : the number of intervals.

Obviously, the degree of the polynomial should be small (5-10), so as not to "overfit" the data and end up with a plot that equals the histogram or something like that.

The number of intervals shouldn't be very large either. I figured that would be plenty. In practice it turned out that is optimal.

So the whole algorithm consists of two stages:

  • Iterating over intervals to build the matrix and the vector.
  • Solving a system of linear equations of size , which is not very large.

There are two ways to iterate over the intervals:

  • Randomly
  • Systematically

In the random case, the most expensive operation is counting the number of points that fall into the interval, which takes if the data is sorted.

If instead we iterate over the intervals systematically, from the minimum to the maximum, we can use the two-pointer technique and know the number of points in the current interval in . And since the number of intervals is , this is the optimal option.

Altogether, the whole algorithm looks like this in pseudocode:

vec = /* 1D vector of size n+1 */
mat = /* 2D matrix of size n+1 */
minv = D[0];
maxv = D[-1];
seg_count = sqrt(K);
step = (maxv - minv) / seg_count;

apos = 0;
for ai in 0..seg_count+1 {
	a = minv + ai * step;
	while apos < M && a > D[apos] { apos += 1; }

	bpos = apos;
	for bi in ai+1..seg_count+1 {
		b = minv + bi * step;
		while bpos < M && b > D[bpos] { bpos += 1; }

		count = (bpos - apos) / M;

		for i in 0..n+1 {
			vec[i] += 2 * count * (b^(i+1) - a^(i+1))/(i+1);
		}

		for i in 0..n+1 {
			for j in 0..n+1 {
				to_add = (b^(i+1) - a^(i+1))/(i+1) 
				       * (b^(j+1) - a^(j+1))/(j+1);

				mat[i, j] += to_add;
				mat[j, i] += to_add;
			}
		}
	}
}

x = solve_SLE(vec, mat)
