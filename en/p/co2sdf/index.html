In all three videos a curved space is a surface, given by an SDF in one more dimension: a function that returns the distance to the surface. A 2D creature lives on a surface in 3D. A 3D creature lives on a hypersurface in 4D. Light travels along the shortest paths of the surface, the geodesics, and the videos follow them with four lines of code. Step along the ray, push the point back onto the surface along the normal, and make the direction tangent again:

float sdf(vec3 p);                          // the world is where sdf(p) == 0

void step(inout vec3 p, inout vec3 dir, float dt) {
    p += dir * dt;                          // step along the ray
    p -= normal(p) * sdf(p);                // push back onto the surface
    vec3 n = normal(p);                     // the normal (the gradient of sdf) at the new point
    dir = normalize(dir - dot(dir, n) * n); // keep the direction along the surface
}

The worlds themselves are built from a handful of small SDF functions. These are the ones used throughout this article:

float ball(vec3 p, float r) { return length(p) - r; }   // a ball; the same with vec2 or vec4 points

// an SDF value d, extruded along the coordinate p from -h to h
float extrude(float p, float d, float h) {
    vec2 w = vec2(d, abs(p) - h);
    return min(max(w.x, w.y), 0.0) + length(max(w, 0.0));
}

// smooth union: the minimum, rounded off where a and b are within k of each other
float smin(float a, float b, float k) {
    float h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0);
    return mix(b, a, h) - k * h * (1.0 - h);
}

// smooth union with a round fillet of radius r
float union_round(float a, float b, float r) {
    vec2 u = max(vec2(r - a, r - b), vec2(0.0));
    return max(r, min(a, b)) - length(u);
}

#22. One dimension up: one number is not enough

❓ Question

What is the framework to work with 2D surfaces in 4D, instead of SDFs, that supports the same level of composition and smooth union?

One equation removes one dimension. In 3D, is a 2D surface, which is why one SDF is enough for a 2D world. In 4D, one equation is a 3D thing, which is right for a 3D world. A 2D world inside 4D needs two equations at once. One dimension down you can see why: a line in 3D is where two planes meet, here a floor and a wall.

Each plane alone is where one number is zero. The world, the line, is where both are zero.

🛠 Terms
  • The world is the space the creatures live in: here the line, later a 2D surface or a 3D space.
  • The codimension is the number of equations you need: the dimension of the space minus the dimension of the world. The videos work in codimension 1. Everything here is codimension 2: 2D worlds in 4D, and 3D worlds in 5D.

So the field returns two numbers, a vec2, and the world is where both are zero. The simplest world, the flat -plane inside 4D, is " and ":

vec2 co2sdf(vec4 p) { return vec2(p.z, p.w); }    // the plane z = 0, w = 0

#23. Pushing a point back onto the world

From here on, colours in the code tell you what kind of value each name holds:

🛠 Types in the code
  • float one number
  • vec2 a pair of numbers (from §9 on, one complex number)
  • vec4, vec5 a point or a direction in 4D or 5D
  • Field a struct of these

With one SDF you push the point along the gradient. With two numbers there are two gradients, the 4D vectors and : is the gradient of the first number , and the gradient of the second number . Both are perpendicular to the world, and together they span the directions that leave it.

We look for a small move that makes both numbers zero. Moving by changes the first number by about and the second by about ; that is what a gradient means. So we want

These are two equations for the four components of , so there are many solutions. Every point of the world near is one: each of them makes both numbers zero. Which one should the push go to? The point we are pushing was just produced by a step along the ray, and the step already decided how far along the world the ray travels and in which direction. The push should only undo the small error of having left the world. Any other solution would also slide the point along the world, moving the ray forward, back or sideways by an amount nobody asked for. So we take the nearest point of the world: the shortest move.

The shortest move goes straight across the world, so it uses only the directions that leave it: for two numbers and . That turns four unknowns into two. Plugging it in gives an ordinary system of two linear equations for and , solved with Cramer's rule. That small solve is the whole trick:

struct Field { vec2 v; vec4 a; vec4 b; };    // both numbers, and the gradient of each

Field field(vec4 p) {                        // numerical gradients: 8 extra samples
    const float h = 1e-4;
    Field F; F.v = co2sdf(p);
    for (int i = 0; i < 4; i++) {
        vec4 e = vec4(0.0); e[i] = h;
        vec2 d = (co2sdf(p + e) - co2sdf(p - e)) / (2.0 * h);
        F.a[i] = d.x; F.b[i] = d.y;
    }
    return F;
}

// the move m = alpha * a + beta * b with dot(a, m) = want.x and dot(b, m) = want.y
vec4 fix(Field F, vec2 want) {
    float aa = dot(F.a, F.a), ab = dot(F.a, F.b), bb = dot(F.b, F.b);
    float det = aa * bb - ab * ab;            // squared area of the parallelogram (a, b)
    float alpha = (want.x * bb - want.y * ab) / det;
    float beta  = (want.y * aa - want.x * ab) / det;
    return alpha * F.a + beta * F.b;
}

vec4 push_back(vec4 p, Field F) { return p - fix(F, F.v); }      // both numbers become 0
vec4 tangent(vec4 v, Field F) {                                  // remove the parts along a and b
    return v - fix(F, vec2(dot(v, F.a), dot(v, F.b)));
}

The same fix does both jobs. Pushing back asks for the move that cancels the two numbers. Making a direction tangent asks for the part of the direction that changes the two numbers, and removes it.

det is the squared area of the parallelogram spanned by the two gradients. If it is zero, the gradients point the same way, the two equations do not really describe a 2D world there, and the push fails. A well-made field keeps the gradients independent everywhere on the world, and the next sections build fields like that. Operators that switch between two formulas, such as union and neck_union, need one extra bit of care for their gradients (§16).

#24. Walking along the world

A ray step is now: move, push back twice, and take the new direction from the step just made:

// F holds the field at p; on return it holds the field at the new p (reuse it next step)
void walk(inout vec4 p, inout vec4 dir, inout Field F, float dt) {
    vec4 q = p + dir * dt;
    q -= fix(F, co2sdf(q));               // first push uses the gradients from the start point
    q = push_back(q, field(q));           // second push with fresh gradients
    F = field(q);
    dir = normalize(tangent(q - p, F));   // new direction: the step itself, made tangent
    p = q;
}

Everything else, the scan, the camera that walks with the mouse, the curvature colours, works exactly as in the videos, with 4D vectors instead of 3D ones. For a 3D world in 5D it is the same code with 5 components.

#25. What the two numbers mean

Stand on the world and look only at the directions that leave it. For a line in 3D they form a disc across the line; for a 2D world in 4D they form a plane in the same way. The world crosses that plane at a single point. A nearby point sits somewhere in it, and the two numbers are its coordinates there:

So the pair is a 2D vector pointing from the world to . Its length is the distance to the world, and its angle says in which direction around the world lies. In 4D you can walk around a 2D world, the way you can walk around a line in 3D, and that angle is how far around you are.

A good field behaves like a good SDF. For an SDF you want the gradient to have length 1, so that the value really is a distance. This is called the eikonal condition. Here you want both gradients to have length 1 and to be perpendicular. Then the length of is exactly the distance, and fix reduces to F.v.x * F.a + F.v.y * F.b. If a field is only roughly like that, nothing breaks; blends just get a bit uneven, as with rough SDFs.

One thing is genuinely new. Rotating the pair does not change the world: rotating by any angle still gives zero exactly on the world. So the angle is a free choice, just as the sign of an SDF is a free choice (you can always flip it). The sign decides which side is inside. The angle decides something similar, which §7 needs for joining worlds. Mathematicians call this freedom a gauge; here it is just "the pair can be rotated".

#Part II. Building worlds

#26. Worlds from SDFs

The easiest way to get two well-behaved numbers is to take two ordinary SDFs. One dimension down, this is how a circle sits in 3D:

  • The carrier is where the world lives: the zero set of the second SDF, a 3D space inside 4D (a plane, in the picture below).
  • The solid is the region where the first SDF is negative, an ordinary solid like the ones in the videos.
  • The world is the boundary of the solid inside the carrier.

In code, a world is just the pair, and each primitive below is one line built from ordinary SDFs:

As with smin, the numbers do not have to stay exact distances once you start combining things. What matters is that both are zero on the world and that their gradients point in different directions there. Which number is the solid and which is the carrier only matters when you join worlds. #27. Joining worlds

Joining works on the solid. Inside one carrier, min, smin and extrude from §1 do what they always did, and the carrier is carried along:

vec2 union(vec2 A, vec2 B)    { return A.x < B.x ? A : B; }
vec2 subtract(vec2 A, vec2 B) { return A.x > -B.x ? A : world(-B.x, B.y); }

vec2 smooth_union(vec2 A, vec2 B, float k) {
    float h = clamp(0.5 + 0.5 * (B.x - A.x) / k, 0.0, 1.0);   // the weight inside smin
    return world(mix(B.x, A.x, h) - k * h * (1.0 - h),         // smin, on the solids
                 mix(B.y, A.y, smoothstep(0.0, 1.0, h)));      // carriers: the same weight, smoothed
}

// extrude, on the solid
vec2 extrude(vec2 A, float p, float h) { return world(extrude(p, A.x, h), A.y); }

There is one rule: pieces you join must have the same carrier where they meet. Inside a shared carrier this is literally ordinary SDF code. Here is a 2D wormhole between two planes, the kind the second video walks through, as a 2D world in 4D. It is the same lines as the 4D wormhole of §1, one dimension down, with a carrier added:

vec2 two_planes_wormhole(vec4 p) {
    float d1 = p.y;
    float d2 = p.y - height;
    float d3 = ball(p.xz, wormhole_size);
    d3 = extrude(p.y - height / 2.0, d3, height);
    float d4 = smin(-d2, d3, smoothing);
    return world(smin(d1, d4, smoothing), p.w);       // the only new part: the carrier
}

The usual tricks on the point work as well, because they change p before either number is computed. Move or rotate a world by evaluating it at the moved point, and scale it with s * world(p / s). Replacing two coordinates by length(p.xy) spins a world around an axis, which is how the donut is built. mod on a coordinate repeats it. On the solid, abs(A.x) - t turns one world into two parallel copies inside its carrier, the onion trick of SDF libraries.

Comparing lengths instead of solids would not work. A tube that ends on a world should cut a hole in it, but the world under the mouth is still at distance zero from itself, so the hole would never open. With the solid, the tube's solid simply covers that disc of the world, exactly as in the wormholes of the videos.

This is also where the free rotation of the pair matters. The first number is "the solid", so rotating the pair rotates which side around the world counts as solid. Two pieces that you join must agree near their junction: same carrier, same solid side. For an ordinary SDF the same thing happens with signs, where you flip signs to choose between union and intersection. Here the choice is an angle instead of a sign.

#3Three parallel worlds, joined pairwise

❓ Question

Three 3D worlds do not fit side by side in 4D, so they had to be bent into U-shapes. In 5D, can three flat worlds simply sit next to each other, joined by cylinders and a smooth union?

Yes. Put three 3D worlds side by side in the two extra directions, at the corners of a triangle. Any two of them lie in one common 4D slice, where they are two parallel planes. In that slice the wormhole between them is the two-planes wormhole, and the carrier is the slice. Do this for the three pairs and join the results with union:

// 3D worlds in 5D at the points c0, c1, c2 of the extra plane p.wv
vec2 wormhole_between(vec5 p, vec2 ci, vec2 cj, vec3 mouth) {
    vec2  e = normalize(cj - ci);
    float L = distance(ci, cj);
    float t = dot(p.wv - ci, e);                    // 0 on world i, L on world j
    float s = dot(p.wv - ci, vec2(-e.y, e.x));      // the carrier: 0 on the slice with both worlds
    float worlds = min(t, L - t);                   // d1 and -d2: beyond the two worlds
    float tube = ball(vec4(p.xyz - mouth, s), r);   // d3; its ends hide in the worlds' solid
    return world(smin(worlds, tube, k), s);
}
vec2 three_worlds(vec5 p) {
    return union(wormhole_between(p, c0, c1, mouth01),
           union(wormhole_between(p, c1, c2, mouth12),
                 wormhole_between(p, c2, c0, mouth20)));
}

The s inside the tube's ball keeps each tube's solid near its own slice. Without it, the tube between worlds 0 and 1 would also punch a hole into world 2.

This joins worlds pairwise. A wormhole for three worlds can also be one wormhole whose three arms meet in the middle. That needs one more operation.

#28. Turning the carrier

Here it is:

// carrier a, turned by angle towards carrier b
float turn(float a, float b, float angle) { return cos(angle) * a + sin(angle) * b; }

Read a and b as two carriers. Where both are zero, the result is zero for every angle, so that set stays where it is, like the hinge of a door. At angle 0 you get carrier a, at 90° carrier b, and in between a carrier tilted between the two. For two flat carriers at right angles, such as p.w and p.y, this is an actual rotation of the carrier around the hinge; for other carriers it is a blend that keeps the hinge fixed. A world whose solid sits around the hinge is cut by this swinging carrier, and its shape changes with the angle. Angles are in radians, as in GLSL.

The angle can change from place to place, which is what makes turn useful: a tube can start in one carrier and end in another. For that the code on this page writes smoothstep. Most pictures use its smoother sibling smootherstep, whose second derivative has no jumps, so the curvature view shows no seams; for the rays the difference is tiny.

#3The donut and the flat torus are one torus

The donut is ball(vec2(ball(p.xy, a), p.z), b): everything within b of the circle . Give the inner ball one more coordinate, p.w, and you have the same thing in 4D: everything within b of that circle, in all four directions. Cut it with the slice and you get the donut. Cut it with the cylinder , which contains the same circle, and you get the flat torus. turn swings between the two:

vec2 torus(vec4 p, float a, float b, float angle) {
    float solid = ball(vec3(ball(p.xy, a), p.z, p.w), b);   // the donut, with w inside the ball
    return world(solid, turn(p.w, ball(p.xy, a), angle));   // 0: a donut; 90 deg: the flat torus
}

Move the angle from 0 to 90 and the orange and blue fade to grey. The reason is visible in the donut. Go once around its tube, and the circles around the hole get longer and shorter again: long on the outside, short on the inside. On a flat sheet that cannot happen: circles placed one after another at equal spacing change length at a steady rate, like the rings of a dartboard, or not at all, like rings around a cylinder. Growing and then shrinking again is what curved surfaces do, like the circles of latitude on a ball. As the carrier turns, the tube's little circle stops moving towards and away from the axis and moves into instead. At 90° every circle around the hole has the same length, both directions close up as on the Asteroids screen, and the torus unrolls into a flat rectangle. (For the whole family to be a proper torus, keep a > b, as for any donut.)

At 90° this is the flat torus of §6: the same points with another pair of numbers. When you only need a flat torus, either pair works. To attach it to something, use this one. Its solid is the donut's, and the donut is the shape that fits into an ordinary world.

#3A flat throat: the torus, extruded

❓ Question

Can a wormhole's throat be flat, by extruding a Clifford torus and connecting it to two planes, so that inside you see yourself repeating without any distortion?

Yes, and the recipe is exactly that: a torus, extruded along the fifth axis, smooth-unioned with two worlds. The only additions are that the torus is flat only in the middle of the throat, and in the collars on either side it turns back into a donut and grows into the mouth:

vec2 flat_throat(vec5 p) {
    float t = clamp((abs(p.v) - 2.5) / 3.0, 0.0, 1.0);    // 0 in the flat middle, 1 at the worlds
    float s = t * t;                                      // the collar: slow at first, fastest at the mouth
    float a = mix(0.5, 3.0, s), b = mix(0.5, 1.5, s);     // the torus grows into the mouth
    vec2 throat = extrude(torus(p.xyzw, a, b, radians(90.0) * (1.0 - s)), p.v, 5.5);
    vec2 worlds = world(5.5 - abs(p.v), p.w);             // beyond the worlds v = -5.5 and v = 5.5, in w = 0
    return smooth_union(worlds, throat, 0.4);
}

The turn is needed because the worlds are flat 3D spaces, and a flat torus does not fit into one. Any closed surface inside ordinary 3D space is curved somewhere: at its point farthest from the centre it bulges like a ball. So where the throat meets a world, its torus cannot be flat; this recipe turns it into a donut, and the mouth in each world is a donut-shaped hole. No 5D torus is needed: every cross-section of the throat, at a fixed , is a torus in , and the fifth coordinate only extrudes it and says how far it has turned and how big it is. The middle stretch of the throat, , is exactly the flat torus times a line, here a square one with a = b = 0.5. In the collars, where the torus turns and grows, and at the mouths, the throat is curved. Each collar is 3 long and ends in a mouth donut with a = 3 and b = 1.5.

In the second picture, up and down is one circle of the torus, forward is the other, and left and right run along the throat. Light that goes mostly up, down or forward stays in the flat part for a long time and shows the spheres again and again, smaller and smaller, without distortion. Every copy is one of the same four spheres, or you, reached by light that went around the torus: the small red ball straight ahead is your own back, a whole circle of the torus away. Light that leans to the left or right leaves through a mouth, into the green world on the left or the orange world on the right. Those worlds come out in many stripes, because on the way out the light can wind around the torus a different number of times.

Without any turning there is an even shorter version, if you allow worlds that wrap around in one direction. Put everything into the carrier ball(p.zw, b): world(smin(7.0 - abs(p.v), extrude(p.v, ball(p.xy, a), 7.0), 0.4), ball(p.zw, b)). That is the two-planes wormhole times a circle. The throat is a flat torus times a line again, and each world is a flat 3D space in which walking far enough in one direction brings you back to where you started.

#3One wormhole for three worlds

In 4D, one wormhole for three worlds is three capsule arms that meet in the middle and are smooth-unioned, with the worlds bent into U-shapes so that they fit. With three flat parallel 3D worlds in 5D the plain version fails, and the reason is easy to see. Each arm leaves its world through the extra directions, and its cross-section is a sphere in that world's own . All three arms would bring the same sphere to the centre, and three tubes with the same cross-section meet in a sharp seam that plain smoothing does not remove.

The fix is to turn each arm's carrier on the way in. Near its world, an arm's carrier is the world's own slice, as for any wormhole. Near the centre all three carriers are the same 4D space, . There the three arms are capsules that meet in one shared 4D space, and an ordinary smooth union joins them, exactly as in the 4D version. The turn happens in the middle of each arm, so both ends, where pieces are blended, have a single carrier.

// 3D worlds in 5D: three worlds at n = rho * d[i] in the extra plane n = p.wv,
// d[i] = unit vectors at 90, 210 and 330 degrees
vec2 arm(vec5 p, vec2 d) {                     // a tube from the centre to the world in direction d
    float along = dot(p.wv, d), side = dot(p.wv, vec2(-d.y, d.x));
    float tube  = capsule(p, vec5(0.0), vec5(0.0, 0.0, 0.0, rho * d), r);
    float angle = radians(90.0) * smoothstep(0.3, 0.7, along / rho);
    return world(tube, turn(p.z, side, angle));   // z = 0 at the centre, the world's slice at the world
}
vec2 parallel_world(vec5 p, vec2 d) {          // the world n = rho * d
    float along = dot(p.wv, d), side = dot(p.wv, vec2(-d.y, d.x));
    return world(extrude(side, rho - along, 0.5), side);    // just beyond the world, near its slice
}
vec2 three_worlds_one_wormhole(vec5 p) {
    vec2 f = smooth_union(smooth_union(arm(p, d[0]), arm(p, d[1]), kj), arm(p, d[2]), kj);
    for (int i = 0; i < 3; i++) f = smooth_union(f, parallel_world(p, d[i]), km);
    return f;
}

capsule is the usual capsule SDF, the distance to a segment minus a radius, in 5D. Each world's solid is "just beyond the world", like the half-spaces of the wormhole in §1, but extruded only half a unit sideways. On the world's own slice that changes nothing, so the world itself stays whole. A full half-space would reach far past the other worlds, and where two such solids meet, smooth_union would blend their different carriers into a ghost world that nobody asked for (§16). The capsule uses all five coordinates for the same reason.

#3A mirror wormhole

❓ Question

Does a higher dimension unlock a mirror?

A handle from a world back to the same world normally keeps you as you are. Turn the tube's carrier by 180° on the way, and you come out mirrored. The handle below is a tube that leaves the plane through mouth 1, arches over it and comes back down through mouth 2. Follow the tube's circle along the way, with an L drawn on it.

In the ordinary handle the circle and its L arrive as they left. In the mirror handle the carrier turns, so the circle turns through , the fourth direction. In our 3D picture that looks like the circle being squashed: at station 4 it points straight into , and all we see of it is a line. After that it opens up again, but now we look at its other face, and the L is mirrored. Anything that walks through the tube is turned over the same way, so a creature comes out of mouth 2 as its own mirror image. The Möbius strip of the second video plays a similar trick by twisting a rectangle, but in 3D that only works because the strip has an edge. Here the turn goes through the extra direction, and the world needs no edge.

// a tube from the mouth x = +R over the plane to the mouth x = -R
vec2 handle(vec4 p, float twist) {
    float solid = ball(vec3(ball(p.xz, R), p.y, p.w), r);   // a 4D donut around the circle |xz| = R
    float along = atan(max(p.z, 0.0), p.x);                 // 0 at x = +R, PI at x = -R
    float angle = twist * smoothstep(0.25 * PI, 0.75 * PI, along);
    return world(solid, turn(p.w, p.y, angle));
}
// twist = 0: an ordinary handle; twist = PI: a mirror handle (the flip fits only these two)
vec2 plane_with_handle(vec4 p, float twist) {
    float flip = twist > 0.0 && p.x < 0.0 ? -1.0 : 1.0;     // the plane, turned over where
    return smooth_union(world(p.z, flip * p.w), handle(p, twist), k);   // the turned mouth arrives
}

The tube is the upper half of a 4D donut standing on the plane; its lower half is hidden inside the plane's solid. The flip line is needed because a mirror world cannot have one smooth pair of numbers everywhere: going around the handle, the pair itself comes back mirrored. So somewhere the field has to jump to its mirror image. On the world both versions are zero, so the jump is harmless, as long as you never take a numerical gradient across it.

#3A wormhole into itself

❓ Question

Can a wormhole lead back into itself? With portals in 3D, a tube from a plane can have its far end glued to itself with no seams: going in, you meet your own image, not mirrored, and you come back out into the same world. Can a 2D world in 4D do this, with its throat connected to itself?

Yes, but for a 2D world it always mirrors you, and no number of dimensions changes that. The far end of a tube can be glued to itself in two ways. Either every point of the end goes to the opposite point of it, or the end is folded, every point going to its mirror point across a diameter. The fold leaves the two points on that diameter where they are, and the fold has a corner at each of them. Only the first way has no seam anywhere.

Count the reversals in the first way. Crossing the end, "down the tube" becomes "up the tube": that is one. For a 3D world the end of the throat is a sphere, and taking every point of a sphere to its opposite is a second reversal, like a mirror. The two cancel, and you come out as you went in: that is the seamless wormhole into itself in 3D, and it is the only seamless way to glue a sphere to itself. For a 2D world the end is a circle, and taking every point of a circle to its opposite only turns it by half a turn. Nothing cancels the first reversal, so you come out mirrored, and the end of the tube has become a Möbius strip.

Nothing else can work for a 2D world. By the Gauss–Bonnet theorem, the total curvature of whatever closes the tube is times its Euler characteristic, and the only piece with one edge whose Euler characteristic is zero is the Möbius strip. Every two-sided closing piece carries curvature somewhere: a cap or a fold carries , the curvature of half a sphere. A round cap spreads it over the cap; the fold puts it all at its two corners. So a 2D world can have a seamless wormhole into itself, or an unmirrored one, but not both. The unmirrored one does not even need 4D. It is a tube squeezed flat at its end, like a toothpaste tube: along the fold it is flat and your twin comes towards you unmirrored, and near the two ends of the fold the view is distorted. A portal can glue the end by the fold exactly; then its two corners are points where the world is folded onto itself, which reflect light straight back and cannot be seen (more on this below). A smooth world has to round them off. (In topology: the 2D version adds a projective plane to the world, which has one side; the 3D version adds projective 3-space, which has two.)

The seamless version needs 4D. In 3D, a Möbius strip whose edge is the mouth of a plane cannot be attached to the plane without crossing it, because a surface that divides space always has two sides (§18). In 4D it fits, flat, and its field is one more turned carrier. Turn the normal plane by twice the angle around the mouth. Seen in the turned frame, the world is just a plane with a dome over the mouth, squashed so that . Then every circle of the dome has the same length in 4D, and the dome is a flat tube. At the top all the turned frames meet, so the top point opens into a whole circle, and the two opposite points of each circle of the dome arrive at the same point of it. That circle is the far end, glued to itself point to opposite point.

// a plane whose mouth leads back into itself: a flat tube of circumference 2 PI R, whose far end
// is glued to itself, every point to the opposite one (a Möbius strip)
vec2 mono_wormhole(vec4 p) {
    float r = length(p.xy);
    float spin = twist * pow(max(1.0 - r * r / (R * R), 0.0), 2.0);   // keeps turning inside: a longer throat
    if (r > 0.5 * R) {
        float angle = 2.0 * atan(p.y, p.x) + spin;     // the normal plane, turned twice as you go around
        float s = turn(p.z, p.w, angle), c = turn(p.w, -p.z, angle);
        return smooth_union(world(s, c), world(ball(vec3(p.xy, 2.0 * s), R), c), k);   // a plane with a dome
    }
    // at the top of the dome the turning breaks down; there: lines through the centre,
    // at half the angle of p.zw (once around, the half angle jumps: a harmless sign flip)
    float half = 0.5 * (atan(p.w, p.z) - spin);
    return world(ball(vec3(p.xy, 2.0 * length(p.zw)), R), turn(p.y, -p.x, half));
}

Without spin the throat is only long. To lengthen it, keep turning the normal plane as you go in: the throat then spirals around the extra plane, which adds length but no curvature, since every circle still has length . At the top of the dome the turned frame is undefined, because at there is no angle around the mouth. There the field uses the other natural description of the throat: straight lines through the centre, at half the angle of p.zw. Once around, that half angle jumps by half a turn and flips the carrier's sign. It is the same harmless cut as the mirror handle's flip, for the same reason: a world that mirrors you cannot have one smooth pair of numbers. As with the flip, gradients are taken on one side of the cut, and of the switch between the two descriptions. The pictures use R = 1, k = 0.15 and twist = 16, a throat 3.6 long. The red creature is you, with a white nose in front and a white ear on its left.

#3Into itself, one dimension up

❓ Question

What about a 3D world in 5D? Does it have two kinds of wormhole into itself, one that mirrors you and one that does not? Or is there one wormhole that does either, depending on where you go in?

Two kinds, and for a smooth world the shape of the mouth decides which you can have. A ball-shaped mouth has a throat whose cross-section is a sphere, and a sphere can be glued to itself, leaving no point in place, in only one way: every point to its opposite. As counted above, that keeps you as you are, so a smooth ball-shaped wormhole into itself never mirrors you. A donut-shaped mouth, like the flat throat of this section, has a torus as its cross-section, and a torus has more seamless ways to be glued to itself: any of its symmetries that move every point. Shift it half way around one of its circles, and the torus stays the same way round; only the trip back up the tube reverses you, so you come out mirrored. Shift it half way around one circle while reflecting the other, and the torus is reversed as well; the two reversals cancel, and you come out as you went in.

One wormhole cannot do both. Every trip through it crosses the glued end once, and the end is glued by a single rule, the same at every point, so whether a trip mirrors you does not depend on where you go in. A throat that forks into two ends glued in different ways would mirror you on one branch and not on the other. And in a world with a mirror in it, being mirrored belongs to the trip, not to the place: go through the mirroring wormhole twice and you are back to normal.

A portal can get both kinds from a ball. The wormhole into itself in the renderer of the videos is a short tube whose end is glued to itself by a portal that takes the left half of the end sphere to the right half: by a reflection, which keeps you as you are, or by a half turn, which mirrors you. Both leave points in place, a whole circle for the reflection and two points for the half turn, and there the world is folded onto itself. Around the circle there is only half a turn of room, and around each of the two points the world is a cone over the projective plane, which is not even a piece of ordinary space. Still nothing shows. Near those points the world is ordinary space folded by a symmetry, so light behaves as in the unfolded space, and a ray that meets the fold comes back as if from a perfect retroreflector. A smooth world cannot do this, in any number of dimensions: it has no such points, and rounding them off puts their curvature where you can see it, as near the corners of the toothpaste tube above. So what limits the field is not the number of extra dimensions but smoothness. The gluings that leave no point in place are exactly the ones a smooth world can copy: the Möbius end for a 2D world, and the opposite-point end for a 3D ball, built below.

The mirroring donut is the 2D wormhole into itself, revolved. Use the distance from an axis instead of , and every half-plane through the axis holds a copy of the 2D world: the mouth becomes a donut, the throat a torus times an interval, and its far end glues every point to the opposite side of the tube's small circle.

// 3D worlds in 5D, p = (x, y, z, w, v): the 2D wormhole into itself, revolved around the z-axis
vec2 mono_donut(vec5 p) { return mono_wormhole(vec4(length(p.xy) - c, p.z, p.w, p.v)); }

In the 3D pictures you are drawn too: a red ball just behind the eye, with a white nose in front, a white ear on its left and a yellow top. (In the 2D views and the playground you are the red creature in the middle.) The pictures use R = 1, twist = 16 and a ring of radius c = 2.6.

The ball-shaped one is harder, because there is no angle around a ball to turn the extra plane by. Its far end is a projective plane, the set of all lines through the centre, and that does not fit into the two extra directions alone; it has to lean into the world's own directions too. Four pieces of field do it. The far end is the family of segments over the directions , where and are the same point: each line through the centre meets the end in one segment, and its two halves are glued. Around it a collar untwists the segments and brings the world down from the height depth to the flat world at a round mouth of radius 2a + width; between, the throat is a sphere times an interval. Two of the pieces need a scalar equation solved by a few Newton steps.

// the ball-shaped wormhole into itself (it keeps you as you are). u = p.xy, h = p.z, v = p.wv
// T + A^2 h^2 / T - A^2 h^4 / T^2 = r^2 and dot(u, u) = (h^2 / q + a^2 q)(1 - q): a few Newton steps each
vec2 mono_ball(vec5 p) {
    vec2 u = p.xy, v = p.wv; float h = p.z, r = length(p.xyz);
    if (r >= 2.0 * a + width) return v;                                        // outside: the flat world
    if (r >= a) {                                                              // the collar, a graph
        float A = a * cutoff(r, a, 2.0 * a), T = collar_root(r * r, h, A);
        vec2 w2 = T * cmul(cmul(u, u), cinv(cpow(vec2(T, -A * h), 2)));
        return v - cutoff(r, 2.0 * a, 2.0 * a + width) * (vec2(depth, 0.0) + b * w2);
    }
    vec2 eta = (v - vec2(depth, 0.0)) / b;
    if (length(eta) < 0.25 && dot(u, u) < h * h / 2.0 + 2.0 * a * a / 9.0) { // around the poles, a graph
        float q = pole_root(dot(u, u), h);
        return v - vec2(depth, 0.0) - b * q * cmul(cmul(u, u), cinv(cpow(vec2(h, -a * q), 2)));
    }
    vec2 Q = cmul(cmul(u, u), cinv(eta));                                      // the middle: closed form
    float s = length(eta);
    return vec2(h + Q.y / (2.0 * a), a * (s - 1.0) + (dot(u, u) / s - Q.x) / (2.0 * a));
}

Here cutoff(r, r0, r1) is a smooth step from 1 below r0 to 0 above r1. The charts are chosen at the point and kept fixed while its gradients are taken, as for the flip above; on the world the field is regular (its gradients never get shorter than 1), and a frame carried through the wormhole comes back the same way round. The construction and its checks are by the fourth codex run of §19. The pictures use a = b = width = 1 and depth = 6.

#Part III. What two numbers add

#29. The pair is a complex number

Everything so far would work with any number of numbers. What makes two special is that a pair can be read as a complex number , so worlds can be multiplied, divided and raised to powers. Rotating the pair, the free choice of §5, is then multiplication by a unit complex number. In code a complex number is just a vec2, with these helpers:

vec2 cmul(vec2 a, vec2 b) { return vec2(a.x * b.x - a.y * b.y, a.x * b.y + a.y * b.x); }
vec2 conj(vec2 z)         { return vec2(z.x, -z.y); }
vec2 cinv(vec2 z)         { return conj(z) / max(dot(z, z), 1e-30); }    // 1 / z
vec2 cexp(float t)        { return vec2(cos(t), sin(t)); }               // the unit number at angle t
vec2 cpow(vec2 z, int n)  { vec2 w = z; for (int i = 1; i < n; i++) w = cmul(w, z); return w; }

Three operations come out of this, one per section: a product of worlds opens their crossing into a wormhole (§10), a root splits one world into several and gives portals (§11), and a power puts extra angle around a point (§12).

This only works for two numbers. Numbers you can multiply and divide exist in 1, 2, 4 and 8 dimensions: real numbers, complex numbers, quaternions and octonions, and nothing in between. So for 3D worlds in 6D, with three numbers, there is no general product and no roots. A few tricks survive, in §10 and §13.

A product of complex numbers is zero when either factor is zero. So cmul(A, B) describes world A and world B together. That is a union, but a crude one: where the two worlds meet, the result is a sharp crossing.

float cutoff(float t) { return 1.0 - smoothstep(0.5, 1.0, t); }   // 1 near the point, 0 beyond k

    return length(A) < length(B)
        ? A - eps * cutoff(length(B) / k) * cinv(B)

    return neck_union(A, B, eps, k);
}

Two practical notes. The formula switches sides at the waist of the neck, so take its gradients from the side chosen at the point where you take them (§16). And at the meeting point itself both worlds are zero and the field is undefined; that point is not on the world, and rays never get there.

#3Three worlds at one point

❓ Question

Can three worlds touch at a single point, and what happens there?

Three planes in general position meet pairwise at three different points, and two nested neck_unions connect every pair. If you put all three planes through one point instead, you get a single junction between all three worlds. Multiply all three, and subtract :

// three planes; every two of them touch at one point
vec2 three_necks(vec4 p) {
    vec2 A = world(p.z, p.w);
    vec2 B = world(p.x, p.y);
    vec2 C = world(p.x + p.z - c, p.y + p.w) / sqrt(2.0);
    return neck_union(neck_union(A, B, eps, k), C, eps, k);
}
// the planes u = 0, v = 0 and u = v all pass through the origin
vec2 triple_point(vec4 p) {
    vec2 u = p.xy, v = p.zw;
    vec2 all = cmul(cmul(u, v), u - v);     // zero on all three: their union, crossing at the origin
    float r2 = dot(u, u) + dot(v, v);
    vec2 open = all - vec2(eps * cutoff(sqrt(r2) / k), 0.0);   // open the crossing
    return open / (r2 + 0.05);                                  // divide to stay distance-like
}

    vec2 h = c * cmul(u, u) / sqrt(dot(u, u) + delta * delta);
    return graph(p.zw, h);
}   // angle around the tip, on large circles: 360 deg * sqrt((1 + 4c^2) / (1 + c^2)), up to 720 deg

Such cones exist in 3D too, which is a surprise: the cone over a wavy closed curve has as much angle as the curve is long, like a ruffled skirt. What 4D adds is the round, symmetric version and a one-line field. A rounded tip always carries curvature that makes up the difference from 360°: here it is negative, the blue of a saddle. For a 3D world the same cone extruded along one more axis gives a line with too much angle around it.

#213. 3D worlds in 5D and 6D

Nothing in the kernel depends on the dimension. In 5D the field still returns two numbers, the gradients have five components, and fix is the same 2×2 solve. GLSL has no vec5; in a shader you keep the world's own vec3 and the two extra coordinates as a vec2, and everything above stays the same. The per-pixel geodesics of the videos' renderer stay as they are.

A 3D world in 6D needs three numbers, and fix becomes a 3×3 linear system. There is no complex-number trick for three numbers (§9), so square roots are gone, and so is a general product. Two things survive. One is the product of three worlds borrowed from quaternions, which joins three worlds at one point (§10). The other is dividing a vector by its squared length, , which is what cinv did for pairs. With it the neck works again. The curvature view needs one formula that the codimension-1 version does not. On a surface in 3D you measure how the normal turns when you step along the surface, and combine the turns as s11 * s22 - s12 * s21. In 4D there are two normals, so what turns is the plane they span. Step along a tangent direction and see how the part of that direction which leaves the world changes. That change is a vector, not a number, so the products become dot products:

// the part of w that leaves the world
vec4 leaving(vec4 w, Field F) { return w - tangent(w, F); }

// p on the world; t1, t2: perpendicular unit tangent directions at p
float gauss_curvature(vec4 p, vec4 t1, vec4 t2) {
    const float h = 0.03;
    Field F1p = field(p + h * t1), F1m = field(p - h * t1);
    Field F2p = field(p + h * t2), F2m = field(p - h * t2);
    vec4 s11 = leaving(t1, F1p) - leaving(t1, F1m);
    vec4 s22 = leaving(t2, F2p) - leaving(t2, F2m);
    vec4 s12 = 0.5 * (leaving(t2, F1p) - leaving(t2, F1m)
                    + leaving(t1, F2p) - leaving(t1, F2m));
    return (dot(s11, s22) - dot(s12, s12)) / (4.0 * h * h);
}

Only the plane spanned by the two gradients enters, not the gradients themselves, so rotating the pair (§5) does not change the result, and neither does a field that switches formulas off the world, as the neck does. For t1, take tangent() of an axis and normalize it; for t2, the same with a second axis, minus its part along t1. In float32, raise the step in field() to 1e-3 for this; the error on a sphere is then under 1%. Checked on known shapes: 1/r² on a round sphere, exactly 0 on the flat torus, and the textbook formula on the neck u·v = ε.

#215. The same thing in geometric algebra

❓ Question

Is projective geometric algebra the answer? Instead of storing two normals, can we store just a bivector?

Partly. For two numbers, geometric algebra and complex numbers turn out to be the same thing, and PGA describes the push-back beautifully, but it cannot do the joining.

🛠 Outer product

In geometric algebra, the outer product of two vectors is the oriented parallelogram they span, called a bivector. Think of it as a small piece of a plane with a size and a direction of rotation. Its squared size is exactly the det in fix. For the two gradients, is the plane of directions that leave the world, the plane drawn in §5. So the normal plane, which needed two normals before, is now one object.

✨ Where complex numbers come from

In geometric algebra a unit bivector multiplied by itself gives , and multiplying a vector in its plane by it rotates that vector by 90°. That is exactly what does. So inside the normal plane, "bivector" behaves exactly like the complex number . The complex numbers of this page are geometric algebra, the part of it that lives in the normal plane. For three numbers (worlds in 6D) the normal space is 3D. There the geometric-algebra object is a trivector, a piece of 3D volume, and its values do not form a number system you can divide in. That is the same statement as in §9, seen from the other side.

🛠 Projective GA (PGA)

Plain geometric algebra only knows directions. PGA adds one extra basis vector for offsets, so a plane that does not pass through the origin is a single object, written as "normal plus offset times ". In PGA, one field evaluation (value and gradient) already is such a plane: the tangent plane of that number. The outer product of two planes is their intersection, : the flat 2D plane that touches the world. fix is the PGA projection of the point onto that flat, . This was checked numerically in 4D and 5D PGA ( and ): the two give the same point to rounding error. PGA is the nicest way to describe the push-back. In a shader the 2×2 solve does the same work with less code.

❌ What PGA cannot do

It is the joining. The outer product of the two planes does not change when you rotate the pair , so it forgets the angle that §7 needs for unions. That is why the code stores the two numbers and not the bivector. In GA terms the object that composes is the bivector together with a chosen direction in its plane: the complex number.

#216. Things that go wrong, and fixes

⚠️ Gradients across a jump

union switches between two pieces. If both pieces describe the same world with different angles (as in the three-world scene, where each world appears in two pairs), the second number jumps right on the world. A numerical gradient taken across the jump is garbage, and the scene produced NaNs until the gradient was taken of the winning piece only. neck_union has the same issue where it switches sides, at the waist of the neck; so does the mirror handle at its flip line. Take the gradient of the selected branch, at the point where you take it. Analytic gradients carried through the operators, a value-plus-gradient struct, do this automatically.

⚠️ Ghost worlds

smooth_union blends the carriers. If two pieces with different carriers blend somewhere, the blend can cancel to zero where no world should be. Building the Y-junction produced exactly that: a stray world far from the wormhole, where the solids of two pieces with different carriers met. The fix is to keep every piece's solid close to its own carrier: the capsule uses all five coordinates, and each world's solid is extruded only a little sideways (§8). A test finds such strays quickly: push thousands of random points onto the field and check that each lands on a piece you meant to build.

⚠️ When one field covers a whole world

For an ordinary world, two-sided and without a mirror twist, you can always write one smooth pair of numbers for the whole thing. For a world that mirrors you, you cannot, and the field needs a cut where it jumps to its mirror image (§8).

⚠️ Accuracy of the push-back

fix pushes to where the straight-line approximation of the world is, so after one push the point is very close to the world but not exactly on it, and a second push is usually enough. That is also why the order of the pushes matters in walk.

⚠️ Kinks in the blend

A smooth union rounded with smin is smooth only once: its curvature jumps where the blend starts. Rays do not mind, but the curvature view shows the jump as a thin seam; smootherstep and a twice-smooth smin remove it.

🛠 What smooth union can mean

Codimension-2 worlds have no inside of their own, so union splits into separate operations depending on how the pieces meet. Pieces that share a carrier near the junction, like a tube ending on a world, use smooth_union; that covers every wormhole mouth. Pieces that cross, at points in 4D or along lines in 5D, use neck_union. Pieces that are apart, like parallel worlds, cannot be joined by anything local; you have to say how, with a tube or with a root. In codimension 2 the honest operation is connect A and B, like this, not one universal smin. Two choices cannot be made canonical: the mirror-image choice of a neck, and the angle alignment between joined pieces when their carriers differ. Both are the codimension-2 version of the sign choice that makes min a union and max an intersection. ❌ Ideas that did not work
  • One number, the plain distance. It has a kink right on the world, like , and its gradient only gives one of the two directions that leave the world. No holes can be cut with it.
  • Storing the bivector instead of two numbers. Good for pushing back, useless for joining, because it forgets the angle. Blending two bivectors also does not give a bivector of a plane any more, and blending two normal-plane projectors does not give a projector.
  • A blend that needs no choice. Blending the two normal planes along the shortest path between them is not unique exactly in the generic case, two perpendicular planes in 4D. The ambiguity is the same choice as above, hidden.
  • Averaging the two fields, mix(A, B, w). Where the two pairs point in opposite directions it cancels, and between two parallel worlds it creates a third world in the middle instead of a connection.
  • Union by length. It never cuts holes (§7).
  • Only exact complex formulas, such as cmul(u, v) - eps with no cutoff. They give beautiful shapes (they are minimal surfaces, like soap films), but the worlds are never exactly flat anywhere: there are no such formulas that are zero outside a region. The cutoff versions trade that beauty for flatness.
  • Three worlds on one ring-shaped slice. Place three worlds around a circular carrier. Walking around the circle you cross three world surfaces, and the inside and outside of the solid would have to flip three times, which cannot close up (an odd number of flips). Two or four worlds work.
  • The Y-junction with straight arms: three tubes with the same sphere meet in a seam that no smoothing removes (§8).

#218. Black holes, mirrors, rotations, cones

❓ Question

Does a higher dimension unlock something like a black hole, a mirror, or a rotation wormhole?

🕳️ Black holes

A horizon is not possible this way: light paths on a surface are reversible, so a smooth world cannot be one-way. What you can render is how a black hole bends light. Light around a non-rotating black hole follows the shortest paths of a curved space, its "optical geometry". In its equatorial plane the circumference at radius is , which has a minimum at the photon sphere, . So that space looks like a wormhole whose throat is the photon sphere, and behind the throat it opens into an endless, ever-widening region where the horizon would be. As a surface of revolution in 3D it can be built down to , an ordinary codimension-1 wormhole; the extra dimension does not help the symmetric version. Rays that pass the throat inward never come back anyway, so you stop them there and colour them black.

🔁 Mirrors

A mirror wormhole in a world without edges needs codimension 2 (§8). So does the seamless wormhole into itself of §8, which for a 2D world always mirrors you; for a 3D world it mirrors you only if its mouth is a donut. A complete world that sits in space as a hypersurface separates space into two sides, so it always has two sides and can never mirror you. The Möbius strip gets around this with an edge. For 3D worlds in 5D the same handle works with the tube's sphere turning through the fifth axis; an explicit mirror-making 3D core in 5D is a twisted bundle of spheres over a circle.

🔄 Rotations

A wormhole that rotates you already exists one dimension down. Going through a round tube carries your directions along the tube's centre line, and a centre line that winds through 4D turns them.

📐 Cones with more than 360°

Yes, round ones in 4D, and wavy ones even in 3D (§12). The 3D-world version is a line with too much angle around it, a "negative-mass cosmic string": the 2D cone extruded along one more axis.

✨ What the extra dimension unlocks
  • Flat worlds that close up in more directions. A complete flat surface in 3D is a cylinder over a curve, so only one direction can close up. In 4D two can: the flat torus, the Asteroids screen. In 5D a 3D world can be flat and closed in two directions, as in the flat throat. A 3D world closed in all three directions, a 3D Asteroids, needs 6D: a closed flat 3D world does not fit into 5D (Tompkins). The flat Klein bottle does fit into 4D (Bushmelev), but as a world that mirrors you it needs the cut of §8.
  • Smooth portals, with any frame shape and any number of worlds.
  • Wormholes from touching worlds, with no tube.
  • Mirror worlds.
  • Room to arrange worlds around each other, as in the triangle of worlds, without bending them.

#2The kernel

The heart of everything is short: two numbers per point, their two gradients by central differences, the 2×2 Gram solve that pushes a point back onto the world (§3), the tangent projection, and the second-order geodesic step with the chord update (§4). At the end of the file the page's library lives under the page's names: ball, extrude, smin, world, smooth_union, extrude_world, turn, roots and the unions with necks.

code/co2sdf.py: the kernel and the library 
"""Reference implementation of complex-valued codimension-2 SDFs ("co2sdf").

A co2sdf is a function F: R^n -> C (numpy complex array, vectorised over the
leading axes of p with p.shape = (..., n)).  The surface is Z(F) = {F = 0}.
Re F is the "solid" SDF inside the carrier, Im F is the SDF of the carrier.
"""
import numpy as np

# ----------------------------------------------------------------------------
# kernel
# ----------------------------------------------------------------------------

def jac(F, p, h=1e-5):
    """Rows a = grad Re F, b = grad Im F (central differences)."""
    n = p.shape[-1]
    a = np.empty(p.shape)
    b = np.empty(p.shape)
    for k in range(n):
        e = np.zeros(n)
        e[k] = h
        d = (F(p + e) - F(p - e)) / (2 * h)
        a[..., k] = d.real
        b[..., k] = d.imag
    return a, b


def dot(x, y):
    return (x * y).sum(-1)


def recip(a, b):
    """Reciprocal frame of (a, b): ra.a = 1, ra.b = 0, rb.a = 0, rb.b = 1."""
    aa, ab, bb = dot(a, a), dot(a, b), dot(b, b)
    det = aa * bb - ab * ab
    ra = (bb[..., None] * a - ab[..., None] * b) / det[..., None]
    rb = (aa[..., None] * b - ab[..., None] * a) / det[..., None]
    return ra, rb


def project(F, p, iters=3):
    """Gauss-Newton projection onto Z(F): p <- p - J^+ F."""
    for _ in range(iters):
        v = F(p)
        a, b = jac(F, p)
        ra, rb = recip(a, b)
        p = p - v.real[..., None] * ra - v.imag[..., None] * rb
    return p


def tangent(a, b, v):
    """Remove the normal-plane part of v (normal plane = span(a, b))."""
    ra, rb = recip(a, b)
    return v - dot(v, a)[..., None] * ra - dot(v, b)[..., None] * rb


def normalize(v):
    return v / np.linalg.norm(v, axis=-1, keepdims=True)


def correct(F, q, a, b):
    """One Newton correction of q with the gradients (a, b) of another point."""
    val = F(q)
    ra, rb = recip(a, b)
    return q - val.real[..., None] * ra - val.imag[..., None] * rb


def geodesic_step(F, p, v, dt, J=None, jet_p=None):
    """Second-order step: first correction along the normal plane at p, one
    correction with fresh normals, new direction = chord projected onto the new
    tangent plane.  Returns (q, v, jet at q); pass that jet back as jet_p."""
    J = J or (lambda x: jac(F, x))
    a, b = jet_p if jet_p is not None else J(p)
    q = correct(F, p + v * dt, a, b)
    q = correct(F, q, *J(q))
    a, b = J(q)
    return q, normalize(tangent(a, b, q - p)), (a, b)


def tangent_frame(F, p, hint1, hint2):
    """Orthonormal tangent frame at p from two hint vectors."""
    a, b = jac(F, p)
    e1 = normalize(tangent(a, b, hint1))
    t2 = tangent(a, b, hint2)
    e2 = normalize(t2 - dot(t2, e1)[..., None] * e1)
    return e1, e2

# ----------------------------------------------------------------------------
# helpers
# ----------------------------------------------------------------------------

def C(x, y):
    return x + 1j * y


def u_of(p):  # complex coordinate of the (x1, x2) plane
    return p[..., 0] + 1j * p[..., 1]


def v_of(p):  # complex coordinate of the (x3, x4) plane
    return p[..., 2] + 1j * p[..., 3]


def smoothstep(e0, e1, x):
    t = np.clip((x - e0) / (e1 - e0), 0.0, 1.0)
    return t * t * (3 - 2 * t)


def smootherstep(e0, e1, x):
    t = np.clip((x - e0) / (e1 - e0), 0.0, 1.0)
    return t * t * t * (t * (6 * t - 15) + 10)


def smin_h(a, b, k):
    """Polynomial smooth min and its blend weight h (h = 1 -> a)."""
    h = np.clip(0.5 + 0.5 * (b - a) / k, 0.0, 1.0)
    return b + (a - b) * h - k * h * (1 - h), h

# ----------------------------------------------------------------------------
# Booleans on co2sdfs
# ----------------------------------------------------------------------------

def union(F1, F2):
    """Hard union: keep the value whose solid (Re) is smaller."""
    return np.where(F1.real <= F2.real, F1, F2)


def intersect(F1, F2):
    return np.where(F1.real >= F2.real, F1, F2)


def subtract(F1, F2):  # F1 minus solid of F2
    G2 = -F2.real + 1j * F2.imag
    return np.where(F1.real >= G2.real, F1, G2)


def fold_union(F1, F2, k):
    """Smooth union of the solids; the carriers are mixed with the same weight."""
    d, h = smin_h(F1.real, F2.real, k)
    w = smoothstep(0.0, 1.0, h)  # C1 weight for the carrier
    return d + 1j * (F2.imag + (F1.imag - F2.imag) * w)


def cutoff(t):
    """1 for t <= 1/2, 0 for t >= 1, C2 in between."""
    return 1.0 - smootherstep(0.5, 1.0, t)


def neck_branch(F1, F2):
    """Which branch neck_union uses at a point (True: the F1 branch)."""
    return np.abs(F1) < np.abs(F2)


def neck_union_on(F1, F2, eps, k, sel):
    """neck_union with a frozen branch choice (for consistent Jacobians: the
    selected field is not smooth across |F1| = |F2| off the surface)."""
    with np.errstate(divide="ignore", invalid="ignore"):
        A = F1 - eps * cutoff(np.abs(F2) / k) / F2
        B = F2 - eps * cutoff(np.abs(F1) / k) / F1
    return np.where(sel, A, B)


def neck_union(F1, F2, eps, k):
    """Union whose transverse crossings are replaced by necks {F1 F2 = eps}.
    Outside |F| > k the pieces are untouched.  Waist radius ~ sqrt(|eps|)."""
    r1, r2 = np.abs(F1), np.abs(F2)
    with np.errstate(divide="ignore", invalid="ignore"):
        A = F1 - eps * cutoff(r2 / k) / F2
        B = F2 - eps * cutoff(r1 / k) / F1
    return np.where(r1 < r2, A, B)

def flat(p, n1, n2, o):
    """Codim-2 flat through o with orthonormal normals n1, n2."""
    d = p - o
    return dot(d, n1) + 1j * dot(d, n2)


def clifford_torus(p, a, b):
    return (np.hypot(p[..., 0], p[..., 1]) - a) + 1j * (np.hypot(p[..., 2], p[..., 3]) - b)


def cone(p, c, m, delta):
    """Graph v = c * u^m / |u|^(m-1) (smoothed). Total angle
    2 pi sqrt((1 + m^2 c^2) / (1 + c^2)).  m = 0 gives an ordinary cone (in R^3)."""
    u, v = u_of(p), v_of(p)
    s = np.sqrt(np.abs(u) ** 2 + delta ** 2)
    if m == 0:
        return v - c * s
    return v - c * u ** m / s ** (m - 1)


def cone_angle(c, m):
    return 2 * np.pi * np.sqrt((1 + m * m * c * c) / (1 + c * c))

# A world is two ordinary SDFs, written here as one complex number
# solid + 1j * carrier: the world is the boundary of the solid, inside the
# carrier (the zero set of the carrier).  The booleans above act on the solid
# and carry the carrier along.

def ball(*xs_and_r):
    """portal_gravity's ball, in any dimension: ball(x, y, ..., r) = |(x, y, ...)| - r."""
    *xs, r = xs_and_r
    return np.sqrt(sum(x * x for x in xs)) - r


def extrude(p, d, h):
    """portal_gravity's extrude: the SDF value d extruded along the coordinate p, from -h to h."""
    wx, wy = d, np.abs(p) - h
    return np.minimum(np.maximum(wx, wy), 0.0) + np.hypot(np.maximum(wx, 0.0), np.maximum(wy, 0.0))


def smin(a, b, k):
    return smin_h(a, b, k)[0]


def capsule(p, a, b, r):
    """Distance to the segment a-b minus r, in any dimension (p: (..., n))."""
    pa, ba = p - a, b - a
    h = np.clip(dot(pa, ba) / dot(ba, ba), 0.0, 1.0)
    return np.linalg.norm(pa - ba * h[..., None], axis=-1) - r


def world(solid, carrier):
    return solid + 1j * carrier


smooth_union = fold_union


def extrude_world(A, p, h):
    """extrude(world, p, h) of the page: the solid extruded along p, the carrier unchanged."""
    return world(extrude(p, A.real, h), A.imag)


def turn(a, b, angle):
    """A carrier turned by `angle` from the carrier a towards the carrier b."""
    return np.cos(angle) * a + np.sin(angle) * b


def roots(n, W, rho, N):
    """N worlds at n = rho * (the N-th roots of W); n and W complex."""
    return rho * ((n / rho) ** N - W) / N

def checker(x, y, size=1.0):
    return ((np.floor(x / size) + np.floor(y / size)) % 2).astype(float)


def shade(base, x, y, size=1.0, lines=True):
    """Checkerboard + thin grid lines + chiral 'L' marks so mirroring is visible."""
    c = checker(x, y, size)
    col = base[None, :] * (0.78 + 0.22 * c[:, None])
    fx = x / size - np.floor(x / size)
    fy = y / size - np.floor(y / size)
    if lines:
        g = (np.minimum(fx, 1 - fx) < 0.03) | (np.minimum(fy, 1 - fy) < 0.03)
        col[g] *= 0.55
    # chiral L glyph in every cell: vertical bar at left + foot at the bottom
    L = ((fx > 0.25) & (fx < 0.35) & (fy > 0.25) & (fy < 0.75)) | \
        ((fx > 0.25) & (fx < 0.6) & (fy > 0.25) & (fy < 0.35))
    col[L] = col[L] * 0.25 + 0.75 * np.array([1.0, 1.0, 1.0])
    return col

class Neck(Scene):

    touching point into a wormhole: {u v = eps} near the origin."""
    name = "neck"
    eps, k = 0.36, 2.4
    cam = np.array([-3.0, 0.0, 0.0, 0.0])

    def F(self, p):
        return neck_union(v_of(p), u_of(p), self.eps, self.k)

    def jac(self, p):
        sel = neck_branch(v_of(p), u_of(p))
        return jac(lambda q: neck_union_on(v_of(q), u_of(q), self.eps, self.k, sel), p)

class ThreeNecks(Scene):
    """Three planes that pairwise touch at single points (three complex lines
    v=0, u=0, u+v=c).  Neck unions at the three touching points."""
    name = "three_necks"
    c, eps, k = 3.0, 0.3, 1.4
    cam = np.array([1.5, -1.8, 0.0, 0.0])

    def parts(self, p):
        u, v = u_of(p), v_of(p)
        return v, u, (u + v - self.c) / np.sqrt(2)

    def F(self, p):
        F1, F2, F3 = self.parts(p)
        return neck_union(neck_union(F1, F2, self.eps, self.k), F3, self.eps, self.k)

    def jac(self, p):
        F1, F2, F3 = self.parts(p)
        s1 = neck_branch(F1, F2)
        s2 = neck_branch(neck_union_on(F1, F2, self.eps, self.k, s1), F3)
        def locked(q):
            G1, G2, G3 = self.parts(q)
            return neck_union_on(neck_union_on(G1, G2, self.eps, self.k, s1), G3, self.eps, self.k, s2)
        return jac(locked, p)

    def color(self, p):
        F1, F2, F3 = self.parts(p)
        d = np.stack([np.abs(F1), np.abs(F2), np.abs(F3)], -1)
        w = np.argmin(d, -1)
        u, v = u_of(p), v_of(p)
        c1 = shade(GREEN, u.real, u.imag)
        c2 = shade(ORANGE, v.real, v.imag)
        # world 3 coordinates: along the line u+v=c, use (u - v)/sqrt2
        s = (u - v) / np.sqrt(2)
        c3 = shade(BLUE, s.real, s.imag)
        return np.where((w == 0)[:, None], c1, np.where((w == 1)[:, None], c2, c3))

class Portal(Scene):
    """N parallel worlds at zeta = rho * omega^k (zeta = x3 + i x4).
    Surface: zeta^N = rho^N W(x), W = (|x|^2 - R^2 + 2iR x2)/(|x|^2 + R^2).
    The segment x2 = 0, |x1| < R is a branch cut = a portal."""
    name = "portal"
    N, rho, R = 2, 1.0, 2.0
    cam = np.array([0.0, -2.5, 1.0, 0.0])
    hint1 = np.array([0.0, 1.0, 0.0, 0.0])
    hint2 = np.array([-1.0, 0.0, 0.0, 0.0])

    def W(self, p):
        x1, x2 = p[..., 0], p[..., 1]
        r2 = x1 * x1 + x2 * x2
        return (r2 - self.R ** 2 + 2j * self.R * x2) / (r2 + self.R ** 2)

    def F(self, p):
        return roots(v_of(p), self.W(p), self.rho, self.N)

    def world_index(self, p):
        # sheet label: which root of W the point is on (principal branch)
        z = v_of(p)
        base = self.rho * np.exp(1j * np.angle(self.W(p)) / self.N) * np.abs(self.W(p)) ** (1 / self.N)
        ks = np.arange(self.N)
        cand = base[..., None] * np.exp(2j * np.pi * ks / self.N)
        return np.argmin(np.abs(cand - z[..., None]), -1)

    def color(self, p):
        w = self.world_index(p)
        out = np.zeros(p.shape[:-1] + (3,))
        for k in range(self.N):
            ck = shade(WORLD_COLORS[k], p[:, 0], p[:, 1])
            out = np.where((w == k)[:, None], ck, out)
        # draw the portal frame (the branch points) as dark dots
        x1, x2 = p[:, 0], p[:, 1]
        near = np.minimum(np.hypot(x1 - self.R, x2), np.hypot(x1 + self.R, x2)) < 0.08
        out[near] = 0.1
        return out

class Handle(Scene):
    """Plane z = w = 0 with a tube from the mouth x = +R to the mouth x = -R: the
    upper half of a 4D donut around the circle |xz| = R (its lower half is
    hidden in the plane's solid).  twist = pi turns the tube's circle over
    through w on the way: the mirror handle."""
    name = "handle"
    R, r, k = 1.5, 0.5, 0.4
    twist = 0.0
    r_max = 10.0
    cam = np.array([-1.5, -2.0, 0.0, 0.0])
    hint1 = np.array([0.0, 1.0, 0.0, 0.0])
    hint2 = np.array([-1.0, 0.0, 0.0, 0.0])

    def handle(self, p):
        x, y, z, w = p[..., 0], p[..., 1], p[..., 2], p[..., 3]
        solid = ball(ball(x, z, self.R), y, w, self.r)              # a donut around the circle |xz| = R, in 4D
        along = np.arctan2(np.maximum(z, 0.0), x)                     # 0 at the mouth x = +R, pi at x = -R
        angle = self.twist * smootherstep(0.25 * np.pi, 0.75 * np.pi, along)
        return world(solid, turn(w, y, angle))

    def plane(self, p, flip=None):
        """The plane; with a twist its carrier is turned over (-w) where the second mouth arrives."""
        x, z, w = p[..., 0], p[..., 2], p[..., 3]
        if flip is None:
            flip = x < 0
        return world(z, np.where(flip & (self.twist != 0), -w, w))

    def F(self, p):
        return smooth_union(self.plane(p), self.handle(p), self.k)

    def jac(self, p):
        # the plane's carrier jumps at x = 0 (mirror handle): differentiate the side p is on
        flip = p[..., 0] < 0
        return jac(lambda q: smooth_union(self.plane(q, flip), self.handle(q), self.k), p)

    def color(self, p):
        left = shade(GREEN, p[:, 0], p[:, 1], 0.6)
        right = shade(np.array([0.2, 0.7, 0.7]), p[:, 0], p[:, 1], 0.6)
        return np.where((p[:, 0] < 0)[:, None], left, right)

class ThreeParallel(Scene):
    """Three parallel planes R^2 x {c_k}; every pair joined by a tube in the
    3-space that contains both planes (an ordinary codim-1 wormhole there);
    the three pair-constructions are combined with the hard (Re-min) union."""
    name = "three_parallel"
    L, r, k = 2.4, 0.55, 0.35
    q = {(0, 1): np.array([-1.6, 0.6]), (1, 2): np.array([1.6, 0.6]), (2, 0): np.array([0.0, -1.6])}
    cam = np.array([0.0, 0.0, 0.0, 0.0])

    def __init__(self):
        rho = self.L / np.sqrt(3)
        ang = np.pi / 2 + 2 * np.pi * np.arange(3) / 3
        self.c = [rho * np.array([np.cos(a), np.sin(a)]) for a in ang]
        self.cam = np.array([0.0, 0.0, self.c[0][0], self.c[0][1]])

    def pair(self, p, i, j):
        ci, cj = self.c[i], self.c[j]
        e = (cj - ci) / self.L
        n = np.array([-e[1], e[0]])
        zx, zy = p[..., 2] - ci[0], p[..., 3] - ci[1]
        t = zx * e[0] + zy * e[1]
        s = zx * n[0] + zy * n[1]
        qq = self.q[(i, j)]
        rx, ry = p[..., 0] - qq[0], p[..., 1] - qq[1]
        cap = np.sqrt(rx * rx + ry * ry + s * s) - self.r
        d, _ = smin_h(np.minimum(t, self.L - t), cap, self.k)
        return d + 1j * s

    def pieces(self):
        return [lambda p, i=i, j=j: self.pair(p, i, j) for (i, j) in [(0, 1), (1, 2), (2, 0)]]

    def F(self, p):
        return union(self.pair(p, 0, 1), union(self.pair(p, 1, 2), self.pair(p, 2, 0)))

    def jac(self, p):
        # hard union: the winner changes phase discontinuously, so differentiate
        # the winning piece only (what analytic gradients would do automatically)
        vals = np.stack([f(p) for f in self.pieces()], 0)
        win = np.argmin(vals.real, 0)
        a = np.zeros(p.shape); b = np.zeros(p.shape)
        for k, f in enumerate(self.pieces()):
            sel = np.nonzero(win == k)[0]
            if len(sel):
                ak, bk = jac(f, p[sel]); a[sel] = ak; b[sel] = bk
        return a, b

    def color(self, p):
        z = p[:, 2:4]
        d = np.stack([np.linalg.norm(z - ck, axis=-1) for ck in self.c], -1)
        w = np.argmin(d, -1)
        out = np.zeros((len(p), 3))
        for k in range(3):
            out = np.where((w == k)[:, None], shade(WORLD_COLORS[k], p[:, 0], p[:, 1], 0.8), out)
        return out

class FlatPortal(Scene):
    """N parallel worlds at n = rho * omega^k (n = x3 + i x4), joined through a
    slit |x1| < R on the line x2 = 0.  Inside the slit strip and outside a box
    around each slit end, the sheets depend on one coordinate only, so the
    space is exactly flat there: only the two ends (the 'frame') are curved."""
    name = "flat_portal"
    N, rho, R, a, T = 2, 1.0, 2.0, 0.6, 1.2
    cam = np.array([0.0, -2.5, 1.0, 0.0])
    hint1 = np.array([0.0, 1.0, 0.0, 0.0])
    hint2 = np.array([-1.0, 0.0, 0.0, 0.0])

    def W(self, p):
        x1, x2 = p[..., 0], p[..., 1]
        frame = 1 - smootherstep(self.R - self.a, self.R + self.a, np.abs(x1))   # 1 inside the frame, 0 outside
        full_turn = np.exp(-2j * np.pi * smootherstep(-self.T, self.T, x2))      # once around 0 while going through
        return 1 + frame * (full_turn - 1)

    def F(self, p):
        return roots(v_of(p), self.W(p), self.rho, self.N)

    def world_index(self, p):
        z = v_of(p)
        Wp = self.W(p)
        base = self.rho * np.abs(Wp) ** (1 / self.N) * np.exp(1j * np.angle(Wp) / self.N)
        cand = base[..., None] * np.exp(2j * np.pi * np.arange(self.N) / self.N)
        return np.argmin(np.abs(cand - z[..., None]), -1)

    def color(self, p):
        w = self.world_index(p)
        out = np.zeros(p.shape[:-1] + (3,))
        for k in range(self.N):
            out = np.where((w == k)[:, None], shade(WORLD_COLORS[k], p[:, 0], p[:, 1]), out)
        return out

class YJunction(Scene):
    """Three parallel worlds R^2 x {rho d_k} joined by ONE three-way wormhole:
    three 4D capsules from the centre to the worlds whose carriers turn from
    y = 0 (at the centre, where the arms share a 3D slice) to the world's own
    slice; each world's solid is a half-space extruded only a little sideways."""
    name = "y_junction"
    rho, r, kj, km, m = 3.0, 0.7, 0.6, 0.4, 0.5
    r_max = 12.0
    hint1 = np.array([0.0, 1.0, 0.0, 0.0])
    hint2 = np.array([-1.0, 0.0, 0.0, 0.0])

    def __init__(self):
        th = np.pi / 2 + 2 * np.pi * np.arange(3) / 3
        self.d = [np.array([np.cos(t), np.sin(t)]) for t in th]
        self.cam = np.array([0.0, -2.2, *(self.rho * self.d[0])])

    def frame(self, p, k):
        d = self.d[k]
        along = p[..., 2] * d[0] + p[..., 3] * d[1]
        side = -p[..., 2] * d[1] + p[..., 3] * d[0]
        return along, side

    def arm(self, p, k):
        along, side = self.frame(p, k)
        tube = capsule(p, np.zeros(4), np.array([0.0, 0.0, *(self.rho * self.d[k])]), self.r)

        return world(tube, turn(p[..., 1], side, angle))

    def parallel_world(self, p, k):
        along, side = self.frame(p, k)
        return world(extrude(side, self.rho - along, self.m), side)

    def F(self, p):
        out = smooth_union(smooth_union(self.arm(p, 0), self.arm(p, 1), self.kj), self.arm(p, 2), self.kj)
        for k in range(3):
            out = smooth_union(out, self.parallel_world(p, k), self.km)
        return out

    def color(self, p):
        z = p[:, 2:4]
        dist = np.stack([np.linalg.norm(z - self.rho * dk, axis=-1) for dk in self.d], -1)
        w = np.argmin(dist, -1)
        out = np.zeros((len(p), 3))
        for k in range(3):
            out = np.where((w == k)[:, None], shade(WORLD_COLORS[k], p[:, 0], p[:, 1], 0.8), out)
        tube = np.min(dist, -1) > 0.35
        out[tube] = out[tube] * 0.55 + 0.45 * GREY
        return out

class MonoWormhole(Scene):
    """A plane whose mouth leads back into itself (the page's mono_wormhole).  The throat is the
    flat Moebius band {|u|^2 + 4|v|^2 = R^2, arg v = 2 arg u + spin(|u|)}, u = x + iy, v = z + iw:
    a flat tube of circumference 2 pi R whose far end is glued to itself, point to opposite point.
    Two charts: away from the centre the normal plane turned by 2 arg u + spin (there the world is
    a plane with a dome); near the centre the band's rulings, lines through the centre at half
    the angle of v (that half angle jumps once around: a sign cut, like the mirror handle's flip)."""
    name = "mono"
    R, k, twist = 1.0, 0.15, 16.0
    r_max = 12.0
    creature = True                      # scans paint a chiral creature at the camera
    cam = np.array([-2.5, 0.0, 0.0, 0.0])
    hint1 = np.array([0.0, -1.0, 0.0, 0.0])
    hint2 = np.array([1.0, 0.0, 0.0, 0.0])

    def spin(self, r):
        t = np.clip(1 - (r / self.R) ** 2, 0, None)
        return self.twist * t * t

    def turned(self, p):
        x, y, z, w = p[..., 0], p[..., 1], p[..., 2], p[..., 3]
        angle = 2 * np.arctan2(y, x) + self.spin(np.hypot(x, y))
        s, c = turn(z, w, angle), turn(w, -z, angle)
        return smooth_union(world(s, c), world(ball(x, y, 2 * s, self.R), c), self.k)

    def central(self, p, psi0=None):
        x, y, z, w = p[..., 0], p[..., 1], p[..., 2], p[..., 3]
        psi = np.arctan2(w, z)
        if psi0 is not None:                                   # continue the branch of psi0
            psi = psi0 + np.arctan2(np.sin(psi - psi0), np.cos(psi - psi0))
        half = 0.5 * (psi - self.spin(np.hypot(x, y)))
        return world(ball(x, y, 2 * np.hypot(z, w), self.R), turn(y, -x, half))

    def field(self, p, inner, psi0=None):
        return np.where(inner, self.central(p, psi0), self.turned(p))

    def F(self, p):
        return self.field(p, np.hypot(p[..., 0], p[..., 1]) < 0.5 * self.R)

    def jac(self, p):
        # the chart and the branch of atan(w, z) are frozen at p: differentiate the side p is on
        inner = np.hypot(p[..., 0], p[..., 1]) < 0.5 * self.R
        return jac(lambda q: self.field(q, inner, np.arctan2(p[..., 3], p[..., 2])), p)

    def throat_tables(self):
        """Flat coordinates of the throat as functions of r = |u|: depth d from the mouth and the
        shift of the around coordinate (sigma = R arg u + shift), from its metric."""
        if getattr(self, "_tab_key", None) != (self.R, self.twist):
            R = self.R
            al = np.linspace(0, np.pi / 2, 4001)                   # r = R cos(al): 0 at the mouth, pi/2 at the far end
            r = R * np.cos(al)
            sp_a = np.gradient(self.spin(r), al)
            e = R * np.sqrt(np.sin(al) ** 2 + 0.25 * np.cos(al) ** 2 + 0.25 * (np.sin(al) * np.cos(al) * sp_a) ** 2)
            f = 0.5 * R * np.sin(al) ** 2 * sp_a
            cum = lambda g: np.concatenate([[0], np.cumsum(0.5 * (g[1:] + g[:-1]) * np.diff(al))])
            self._tab = (r[::-1], cum(e)[::-1], cum(f)[::-1])
            self._tab_key = (self.R, self.twist)
        return self._tab

    @property
    def length(self):
        return self.throat_tables()[1][0]

    def color(self, p):
        rr, dd, ss = self.throat_tables()
        r = np.hypot(p[:, 0], p[:, 1])
        sigma = self.R * np.arctan2(p[:, 1], p[:, 0]) + np.interp(r, rr, ss)
        throat = shade(TEAL, np.mod(sigma, 2 * np.pi * self.R), np.interp(r, rr, dd), 2 * np.pi * self.R / 12)
        return np.where((r < self.R)[:, None], throat, shade(GREEN, p[:, 0], p[:, 1], 0.5))

    def creature_coords(self, pos, cam, e1, e2):
        """The camera frame in the throat's flat coordinates, unfolded across the far end: a point
        (sigma, d) is also (sigma + pi R, 2 L - d) on the other side of the glued end."""
        R, L, C = self.R, self.length, 2 * np.pi * self.R
        rr, dd, ss = self.throat_tables()
        def flat(q):
            r = np.hypot(q[..., 0], q[..., 1])
            return R * np.arctan2(q[..., 1], q[..., 0]) + np.interp(r, rr, ss), np.interp(r, rr, dd), r
        sc, dc, rc = flat(cam)
        if rc >= R:                                          # camera on the plane: the plane is flat too
            a1, a2 = (pos[:, :2] - cam[:2]) @ e1[:2], (pos[:, :2] - cam[:2]) @ e2[:2]
            return a1, a2, np.hypot(pos[:, 0], pos[:, 1]) > R + 0.2
        s, d, r = flat(pos)
        wrapc = lambda x: (x + 0.5 * C) % C - 0.5 * C
        ds1, dd1 = wrapc(s - sc), d - dc
        ds2, dd2 = wrapc(s + 0.5 * C - sc), (2 * L - d) - dc
        use2 = np.hypot(ds2, dd2) < np.hypot(ds1, dd1)
        ds, dd_ = np.where(use2, ds2, ds1), np.where(use2, dd2, dd1)
        # e1 points along -theta (decreasing sigma), e2 towards the far end (increasing d)
        return -ds, dd_, r < R

    def at_depth(self, frac, theta=np.pi):
        """A point of the throat at a fraction of its depth, with the frame (around, towards the far end)."""
        rr, dd, _ = self.throat_tables()
        r = np.interp(frac * dd[0], dd[::-1], rr[::-1])
        def P(al, th):
            r = self.R * np.cos(al); rho = 0.5 * self.R * np.sin(al); ang = 2 * th + self.spin(r)
            return np.array([r * np.cos(th), r * np.sin(th), rho * np.cos(ang), rho * np.sin(ang)])
        al, h = np.arccos(r / self.R), 1e-4
        return P(al, theta), -(P(al, theta + h) - P(al, theta - h)) / (2 * h), (P(al + h, theta) - P(al - h, theta)) / (2 * h)

"""Regular chartwise field for a punctured RP^3 in R^5.  Only numpy is needed.

Coordinates are (Re u, Im u, h, Re v, Im v).  Select a chart once at each
Newton evaluation, and keep that selection fixed for numerical gradients.
"""
from dataclasses import dataclass
import numpy as np


def cutoff(r, start, end):
    """C-infinity: one for r <= start, zero for r >= end."""
    s = (np.asarray(r, dtype=float) - start) / (end - start)
    out = np.ones_like(s)
    out[s >= 1] = 0
    mask = (s > 0) & (s < 1)
    q = s[mask]
    # chi = sigmoid(1/q - 1/(1-q)); stable even very near an endpoint.
    log_ratio = 1 / q - 1 / (1 - q)
    out[mask] = np.exp(-np.logaddexp(0, -log_ratio))
    return out


@dataclass
class Wormhole:
    a: float = 1.0
    b: float = 1.0
    depth: float = 6.0
    width: float = 1.0

    def __post_init__(self):
        assert self.a > 0 and self.b > 0 and self.width > 0
        assert self.depth > self.b

    @property
    def mouth_radius(self):
        return 2 * self.a + self.width

    def twist(self, r):
        return self.a * cutoff(r, self.a, 2 * self.a)

    def height(self, r):
        return cutoff(r, 2 * self.a, self.mouth_radius)

    def charts(self, points):
        """0=flat/far, 1=outer graph, 2=middle, 3=pole, 4=empty."""
        p = np.atleast_2d(points)
        u = p[:, 0] + 1j * p[:, 1]
        h = p[:, 2]
        v = p[:, 3] + 1j * p[:, 4]
        r = np.linalg.norm(p[:, :3], axis=1)
        eta = (v - self.depth) / self.b
        far = (r >= self.mouth_radius) | (
            np.abs(v) > self.depth + self.b + self.a)
        outer = (~far) & (r >= self.a)
        pole = (~far) & (~outer) & (np.abs(eta) < 0.25) & (
            np.abs(u)**2 < h*h/2 + 2*self.a*self.a/9)
        # The middle formula is also valid below its usual threshold.  Use
        # it when an off-world point leaves the pole graph's domain.
        middle = (~far) & (~outer) & (~pole) & (np.abs(eta) > 0)
        result = np.full(len(p), 4, dtype=int)
        result[far] = 0
        result[outer] = 1
        result[middle] = 2
        result[pole] = 3
        return result

    def outer_root(self, r2, h, A):
        """T + A^2 h^2/T - A^2 h^4/T^2 = r^2, physical root.

        For r >= a and 0 <= A <= a, derivative >= 5/6 on the
        physical bracket.  Eight clipped Newton iterations suffice here.
        """
        r2, h, A = np.broadcast_arrays(r2, h, A)
        lo = np.maximum(h*h, r2 - A*A/4)
        T = r2.copy()
        if np.all(A == 0):
            return T
        for _ in range(8):
            q = h*h/T
            f = T - r2 + A*A*q*(1-q)
            df = 1 + (A*A/T)*(2*q*q-q)
            T = np.clip(T-f/df, lo, r2)
        return T

    def pole_root(self, U, h):
        """Unique q in (2/3,1] with U=(h^2/q+a^2*q)*(1-q)."""
        U, h = np.broadcast_arrays(U, h)
        q = np.ones_like(U)
        for _ in range(12):
            f = U - (h*h/q + self.a*self.a*q)*(1-q)
            df = h*h/(q*q) + self.a*self.a*(2*q-1)
            q = np.clip(q-f/df, 2/3, 1)
        return q

    def field(self, points, frozen=None):
        single = np.asarray(points).ndim == 1
        p = np.atleast_2d(np.asarray(points, dtype=float))
        chart = self.charts(p) if frozen is None else np.broadcast_to(frozen, (len(p),))
        result = np.zeros((len(p), 2))
        for code in range(5):
            mask = chart == code
            if not np.any(mask):
                continue
            part = p[mask]
            u = part[:, 0] + 1j * part[:, 1]
            h = part[:, 2]
            v = part[:, 3] + 1j * part[:, 4]
            if code == 0:
                value = v
            elif code == 1:
                r2 = np.sum(part[:, :3]**2, axis=1)
                r = np.sqrt(r2)
                A = self.twist(r)
                T = self.outer_root(r2, h, A)
                w2 = T*u*u/(T - 1j*A*h)**2
                value = v - self.height(r)*(self.depth + self.b*w2)
            elif code == 2:
                eta = (v - self.depth)/self.b
                s = np.abs(eta)
                Q = u*u/eta
                result[mask, 0] = h + Q.imag/(2*self.a)
                result[mask, 1] = self.a*(s-1) + (
                    np.abs(u)**2/s - Q.real)/(2*self.a)
                continue
            elif code == 3:
                q = self.pole_root(np.abs(u)**2, h)
                w2 = q*u*u/(h - 1j*self.a*q)**2
                value = v - self.depth - self.b*w2
            else:
                value = np.full(len(part), self.a, dtype=complex)
            result[mask] = np.column_stack((value.real, value.imag))
        return result[0] if single else result

    def jacobian(self, points, step=1e-5, frozen=None, order=4):
        """Frozen-chart finite difference Jacobian, order 2 or 4."""
        single = np.asarray(points).ndim == 1
        p = np.atleast_2d(np.asarray(points, dtype=float))
        chart = self.charts(p) if frozen is None else frozen
        result = np.empty((len(p), 2, 5))
        for j in range(5):
            offset = np.zeros(5)
            offset[j] = step
            plus = self.field(p + offset, chart)
            minus = self.field(p - offset, chart)
            if order == 2:
                result[:, :, j] = (plus-minus)/(2*step)
            else:
                plus2 = self.field(p + 2*offset, chart)
                minus2 = self.field(p - 2*offset, chart)
                result[:, :, j] = (8*(plus-minus)-(plus2-minus2))/(12*step)
        return result[0] if single else result

    @staticmethod
    def pack(u, h, v):
        return np.stack((u.real, u.imag, h, v.real, v.imag), axis=-1)

    def core(self, t, d):
        d = np.asarray(d)
        w = d[..., 0] + 1j*d[..., 1]
        z = d[..., 2]
        return self.pack((t-1j*self.a*z)*w, t*z,
                         self.depth+self.b*w*w)

    def core_limit(self, d):
        q = np.asarray(d)[..., 2]**2
        return self.a*np.sqrt(1-q*(1-q))

    def collar(self, r, d):
        d = np.asarray(d)
        r = np.asarray(r)
        w = d[..., 0] + 1j*d[..., 1]
        z = d[..., 2]
        A = self.twist(r)
        t = np.sqrt(r*r-A*A*z*z*(1-z*z))
        return self.pack((t-1j*A*z)*w, t*z,
                         self.height(r)*(self.depth+self.b*w*w))

    def project(self, points, tolerance=1e-12, max_steps=16, step=1e-5):
        p = np.atleast_2d(np.asarray(points, dtype=float)).copy()
        count = np.zeros(len(p), dtype=int)
        initial_chart = self.charts(p)
        changes = np.zeros(len(p), dtype=bool)
        valid = initial_chart != 4
        for _ in range(max_steps):
            chart = self.charts(p)
            changes |= chart != initial_chart
            f = self.field(p, chart)
            active = valid & (np.linalg.norm(f, axis=1) > tolerance)
            if not np.any(active):
                break
            J = self.jacobian(p[active], step=step, frozen=chart[active], order=2)
            gram = J @ np.swapaxes(J, 1, 2)
            try:
                multipliers = np.linalg.solve(gram, f[active, :, None])[..., 0]
            except np.linalg.LinAlgError:
                raise RuntimeError("Newton reached a singular off-world chart")
            p[active] -= np.einsum('nki,nk->ni', J, multipliers)
            count[active] += 1
            valid &= self.charts(p) != 4
        residual = np.linalg.norm(self.field(p), axis=1)
        return p, count, residual, changes, valid
